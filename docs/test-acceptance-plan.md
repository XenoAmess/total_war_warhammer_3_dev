# 征募与迁都：测试验收与发布方案

日期：2026-10-30。适用版本：本项目首个双功能版本。需求与边界以 [设计文档](mod-design.md) 为准。

## 1. 验收层次

| 层次 | 执行内容 | 能证明的范围 |
| --- | --- | --- |
| L0 静态与包检查 | Lua 5.1 语法、资源清单、本地化 key、重复文件、包重开与哈希 | 文件结构与语法正确，不能代替游戏行为 |
| L1 离线业务测试 | 角色保护、请求去重、过期快照、部分失败、首都资格 | 真实生产模块在模拟接口下的决策正确 |
| L2 原版引擎原型 | 候选查询、生成、删除、迁都、按钮创建与点击 | 已安装游戏版本实际支持关键接口 |
| L3 单人战役验收 | 两类招募刷新、迁都、持久化和失败处理 | 声明支持的实际玩家流程有效 |
| L4 创意工坊发布验证 | 上传回执、公开页面、内容与说明、下载包核对 | 发布到正确 App 与条目，并可公开获得 |

每层分别给出 PASS、FAIL、NOT_RUN 或 BLOCKED。跳过不算通过。L0/L1 通过不授予 L2/L3 通过；上传回调成功不授予公开发布成功。

## 2. 测试环境与隔离

记录机器 ID、UTC 时间、Steam App/Build ID、EXE SHA-256、源码 commit、正式 `.pack` SHA-256，以及测试日志位置。当前已知游戏为 `9.0.4.0`、App `1142710`、Build `25961564`；启动前重新确认。

使用专门测试存档和单人超凡帝国战役，不覆盖玩家既有存档。不将测试夹具、自动操作脚本、调试菜单、游戏本体和个人配置打入正式包。测试夹具直接调用正式生产模块，同时保留至少一次正式按钮点击的完整操作证据。

游戏首次运行或配置缺失时记录实际情况；只改变验收需要的本机配置，先保存原始字节，结束后恢复本次临时修改。原有其他 Mod 不作为默默关闭的对象：用独立测试启动配置隔离。

## 3. L0/L1 自动检查

| 编号 | 输入 | 必须满足 |
| --- | --- | --- |
| A01 | 全部正式 Lua | 按 Lua 5.1 编译成功；不是仅在开发机新版 Lua 运行 |
| A02 | 中文与英文文案 | key 集合相同、无重复 key、引用存在；正式包仅有一套有效译文 |
| A03 | 构建两次 | 相同输入生成相同包与清单；重开后路径、大小、内容哈希全部对应 |
| A04 | 唯一、不朽、受伤、曾招募、未知来源等候选 | 全部被保护，不进入删除集合 |
| A05 | 两个子类型混合池 | 仅当前子类型、同派系、已证明普通的新候选可替换 |
| A06 | 重复、未知动作、过期回合、错误派系请求 | 拒绝或返回已有结果；不重复修改 |
| A07 | 创建失败、生成不完整、删除失败、读回不明 | 停止后继删除；明确部分完成或结果不明 |
| A08 | 迁都至自有、敌方、废墟、当前首都和无首都派系 | 资格符合设计；错误请求不修改首都 |

不为文档或配置常量增加镜像实现式测试。A04–A08 使用正式业务模块与可注入游戏适配器，覆盖实际分支和副作用次数。

## 4. L2 原型实验

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| P01 | 在领主和事务官招募页取得当前候选 | 得到稳定人物 ID、子类型和身份信息，确认未把地图人物当候选 |
| P02 | 创建一个普通领主和一个普通事务官候选 | 姓名、外观、背景、原生招募资格和费用有效 |
| P03 | 对明确可替换的一个候选执行清理 | 旧人物离池；受保护人物、军队及其他类别不变 |
| P04 | 在原生满池时创建替代候选 | 临时超额不淘汰无关人物；否则调整替换算法后重新验证 |
| P05 | 迁都后查询模型 | `home_region` 等于目标，所有权/建筑/省会身份不变 |
| P06 | 三种面板注入并点击自有按钮 | 真实点击触发相应生产请求、显示结果，无重复按钮 |

原型优先验证风险最大的 P01–P04。不能安全替换时继续修正实现与设计，不把自然每回合刷新、只增加人物或重掷特性当完整刷新通过。

2026-10-31 原生路径补充：检查 memreader Plus 缺失、函数签名不唯一及调用链变化时，是否在生成之前停止。实机必须先关闭原生 HUD 招募页，等待关闭完成后再清理旧候选；重开后逐张核对卡片 ID 与模型一致，然后读取姓名/头像并正常招募。仅后台 ID 替换成功不能通过界面验收。最终冻结包需通过常规 mod 加载，测试命令记录器使用 `--dispatcher-only`，不内嵌生产文件，不热加载源码。

## 5. L3 业务矩阵

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| G01 | 普通领主子类型实际按钮刷新 | 可替换旧 ID 消失、新 ID 可招募，人数不累积 |
| G02 | 普通事务官子类型实际按钮刷新 | 同 G01，且事务官容量和已部署人物保持 |
| G03 | 传奇、受伤、已解散及未知来源人物 | 刷新前后受保护人物一致；未知人物有明确解释 |
| G04 | 连续 10 次刷新，再正常过回合 | 无候选泄漏/无限累积/空白姓名；自然更新正常 |
| G05 | 取消确认、切换目标、重复事件 | 取消不修改；旧快照拒绝；一次请求最多执行一次 |
| G06 | 迁都到自有小城与省会 | 模型与首都显示正确；原版城市属性保持 |
| G07 | 非自有/当前首都/无有效目标 | 正确禁用和拒绝，不改其他派系 |
| G08 | 刷新、迁都后保存并重新载入 | 候选与首都正确；请求状态没有被重放 |
| G09 | 重开 UI、缩放与类别切换 | 组件不重复、可读可点、不作用于错误页面 |
| G10 | 特殊招募/联机/未支持战役 | 明确禁用，不绕过训练、仪式和特殊资源 |
| G11 | 注入不完整执行并重载 | 操作可诊断；结果未明时不自动追加删除 |

正式首版的两个核心功能 G01/G02/G06 和角色保护 G03 必须全部通过。支持范围按实际测过的派系/子类型列出，不推断全种族兼容。额外组合 Mod、首都失守和卸载实验按设计 T12/T15/T16 独立报告；未测范围不写成兼容承诺。

## 6. 证据与结果

结果报告保存到 `docs/acceptance-report.md`，机器可读摘要保存到 `docs/acceptance-results.json`。大体积运行日志、截图和测试存档置于仓库外的本机验收目录，报告记录精确文件名、SHA-256 和关键模型前后状态；不上传私人存档。

每次刷新记录请求序号、派系、子类型、旧/新/受保护人物 ID；迁都记录前后地区 key。截图证明交互位置，模型读回证明业务结果。失败保留原始诊断，修复后的新结果追加记录，不删除首次失败事实。

## 7. L4 发布验收

1. 冻结已验收正式包、资源清单、版本号、源码 commit 与 SHA-256。发布目录只放正式包，预览图另传；不上传整个仓库。
2. 使用当前登录的 Steam 账号向 App `1142710` 创建一个条目；收到 ID 后立即持久化，后续重试更新同一条目，避免重复创建。
3. 设置中文标题、完整功能说明、首版支持范围、限制、Change Notes、预览图和公开可见性。
4. 等待实际上传结束，保存回执。若需要工坊协议或登录操作，记录平台返回的具体要求，不伪造成功。
5. 匿名回读该条目，核对 App、所有者、标题、说明、可见性及更新记录。检查上传内容哈希；能正常下载时核对下载包与正式包一致。
6. 写入 `docs/workshop-publication.md`，提供条目链接、版本、上传时间与真实验证边界；提交并推送。

发布前核心功能未通过时不把存在已知错误的包标成已验收版本。若外部平台阻断发布，保留已完成代码、正式构建和证据，并明确停在哪一步。
