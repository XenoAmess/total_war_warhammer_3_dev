# Changelog

## 0.3.3 — 2026-11-18（已验收，未上传工坊）

- 接入混矮独立武装车队的运输将领列表、标题旁刷新图标及正确的关闭／恢复路径，原生修改保护同时检查此面板。
- 保存实际选中的法术系标签和容器，兼容领主法术系键与英雄亚种键；修复死亡系已刷新却返回默认哈苏特系的问题。
- 197 项离线测试通过。最终冷启动包通过混矮车队两次 1→1、闲置及在途保护、原生派遣、刷新后雇用与护卫核对、空池保护、死亡系领主 2→3／返回死亡系／正常雇用，以及与迁都 0.2.0 共同启用验收。
- 迁都目标转让和原版车队容量科技瞬时研究属于夹具，不算攻城或完整研究流程。巴什瓦仍未拥有，其余 DLC 派系及有限池未逐项实测，联机未原生验收。详见 [DLC 报告](docs/dlc-compatibility-20261118.md)。

## 0.3.2 — 2026-11-16（已发布）

- 接入震旦督运总督、混矮车队监督与巴什瓦商队候选：保留人物身份、姓名及名额，按原版权重排除旧背景重抽；排除在途及闲置的已拥有商队，刷新后返回商队招募页。通用生成人物接口不用于商队。
- 类型发现扩展到血裔、史兰及有随机背景的晋升／召唤类型的现有候选池；保持特殊池人数，不新增解锁，复制并核验附加特性的原始点数。人物的履历、唯一、不朽、开局及已招募等保护继续生效。
- 新特殊池预检培养进度；任一待替换候选有额外经验、点数或技能时拒绝整次刷新。默认自带技能按原版创建点数识别，不当作额外培养。
- 冰雪宫廷训练结果不重抽；固定王朝国王、科技专属军阀、黑色方舟及龙舰提督等专属身份继续排除。
- 修复生成已经发生但人物描述读回失败时可能误报为普通拒绝的问题；现在记录新人物 ID、锁定不确定结果，不继续删除旧人。
- 90 项共用、102 项专属离线测试通过。精确最终包通过震旦两次 1→1、正常雇用、按新背景生成护卫队及已有商队保护，史兰 1→1、附加特性点数和默认技能保留及正常雇用。史兰使用原版仪式生成人物函数及附加特性夹具，不算完整仪式流程验收。混矮／巴什瓦无本机授权，未直接实测；其余有限池未逐类型实测，联机未实机验收。见[实现、失败路径与验收记录](docs/special-recruitment-implementation-0.3.2.json)。

- 原工坊条目更新完成；公开正文、更新日志、启动器元数据、封面和原图库核对通过，真实订阅下载包与验收包哈希一致，订阅包前端载入身份读回通过。测试装载及偏好文件已恢复，Steam 已恢复主动离线。见[发布回执](docs/workshop-publication-0.3.2.json)。

## 0.3.1 — 2026-11-16（已发布）

- 修复同职业多子类型页面可能刷新错误法术系的问题：优先读取当前选中的可见候选，随后才考虑职业缓存；未选中时只接受子类型一致的列表。
- 同时识别原生 `selected` 与 `selected_hover`，覆盖鼠标仍悬停在选中分类或候选上的情况；读取失败、特殊人物或混合列表不再退回另一缓存类型。
- 修复刷新后重开面板返回默认法术系：等待职业页重建后恢复原生法术系页签，再读取实际候选；缺少或隐藏的页签不强行记作已选中。
- 刷新前记录当前可见原生分类，覆盖高精王子等分类名与人物类型不同的页面，刷新后恢复该分类。
- 开局先保留人物入池事件，再在初始化后识别类型，避免池元数据尚未就绪时丢失普通候选履历；原有特殊人物、已招募人物及未知旧存档履历保护继续生效。
- 90 项共用、82 项专属离线测试通过。精确最终包通过 9.0.5 高精单机实测：生命系 1→3、高等系 6→6、王子 4→4、未知履历保护、正常招募及按钮避让，其他池保持不变。
- 本机缺少巴什瓦角色包授权，爪语者未直接实测；用户确认以同机制实测并披露后发布。联机仍未实机验收。见[实机报告](docs/native-acceptance-0.3.1.md)与[调查记录](docs/clawspeaker-refresh-0.3.1.md)。
- 原工坊条目更新完成，公开正文/更新日志、封面、原图库、启动器元数据及实际订阅包哈希核对通过；普通 Steam 客户端主动离线读回完成。见[发布回执](docs/workshop-publication-0.3.1.json)。

## 0.3.0 — 2026-11-11（已发布）

- 增加实验性多人同步：所有端关闭人物面板、比对包/依赖/候选状态，统一执行并核对结果；重复请求和中断保护覆盖两个 Mod。
- 类型检查使用请求派系，候选指纹覆盖保护资格和生成参数；补员性别模板按稳定 ID 选取，避免枚举顺序造成差异。
- 修复游戏事件长度截断：单机使用一次性短引用传递冻结请求，联机使用小分片，避免完整候选快照被截成失效请求。
- 单机继续单击直接刷新、不足 3 人补足、保护特殊候选；商队/车队仍禁用。
- 按用户要求不做联机实机验收，不据离线模拟宣称已验证多人稳定性。见[协议与限制](../../docs/multiplayer-transport.md)。

## 0.2.4 — 2026-11-05

相对工坊 0.2.2，包含未单独发布的 0.2.3 修复：

- 手动刷新将选中的非空普通招募子类型补足到至少 3 名。已有更多候选时保持人数，重复刷新不持续增加。
- 受保护人物保留；原版费用、容量、建筑及内容解锁检查保持。空池和特殊招募不扩充。
- 增加精确引擎构建校验，已验证 Windows x64 9.0.4 / 9.0.5；未验证构建禁用原生刷新。
- 商队、车队类型在支持检查、生成及原生定位前拒绝，避免误入普通候选刷新。
- 改善原生池校验失败及面板关闭失败提示，保留部分完成、结果不明时的锁定保护。
- 9.0.5 基斯里夫离线实机验证 1→3、2→3、5→5、保护人物保留、新增候选正常招募及按钮避让。未单独验证用户截图中的纳垢英雄，不宣称全种族兼容。

Refresh now fills a selected nonempty ordinary subtype pool to at least three candidates. Larger pools retain their size; protected characters and normal recruitment requirements remain. This release also adds verified engine-build checks, excludes caravan/convoy recruitment, and clarifies validation errors. Native regression passed on Kislev in Windows x64 game 9.0.5.

完整工坊中英双语更新说明见 [change-notes.txt](workshop/change-notes.txt)，实机记录见 [0.2.4 验收](docs/candidate-count-0.2.4.json)。
