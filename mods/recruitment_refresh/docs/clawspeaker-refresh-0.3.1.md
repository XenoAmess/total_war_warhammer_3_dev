## 已确认的共用缺陷

1. **职业缓存先于候选选择。** 0.3.0 先从已发现的子类型推断原生职业标签。若只缓存了一种法师，而当前选择是尚未发现的另一系，就会先确定旧类型，跳过当前候选读取；多个缓存类型时，上一目标也可能先于当前卡片生效。新增真实控制器回归在旧实现失败。现在保留精确子类型标签，职业共用标签则优先读取当前可见候选：同时检查外层卡片与 `button_wh3` 的选中状态。没有选择时，只接受全部可见卡片属于同一子类型；特殊、不可读或歧义列表禁用刷新，不能退回另一缓存类型。隐藏页面、隐藏卡片与隐藏列表祖先不提供目标。
2. **漏认悬停选中状态。** 9.0.5 原生招募标签在隔离测试中返回 `selected_hover`，旧实现只认 `selected`。分类标签、职业标签及候选统一接受这两个状态，避免鼠标停在刚点击的法术系时丢失选择。没有扩大为任意状态前缀。
3. **开局观察可能在排队前丢失。** `observe_entry` 原先先查询依赖候选池的类型元数据，再判断是否初始化。元数据尚不可读时，事件直接返回，人物 ID 没有进入待处理队列。现在先排队，初始化后经原有类型与人物保护检查重放。回归覆盖普通、起始、唯一、不朽、已招募及重复观察；未观察的旧存档人物不补造履历，也不清除未知/部分执行锁。

上述问题不限于爪语者，也适用于共享职业标签的其他多法术系领主/事务官。离线用例明确覆盖爪语者生命、野兽、阴影三系（原版职业为 `spy`）、帝国火焰法师（`wizard`）、单一/多个/不完整类型缓存、外层/内层卡片的 `selected`/`selected_hover`，以及隐藏与歧义输入。没有通过白名单放行商队、车队或冰雪宫廷。
